## 修复打卡时间8小时偏移问题

**问题**：App端打卡后显示时间比实际时间差8小时（如凌晨00:14打卡显示16:14）

**根因**：`mysql2` 驱动读取 MySQL DATETIME 时，默认假设数据库时区为 UTC，将北京时间 `00:14:38` 错误转为 UTC Date 对象 `T16:14:38Z`（减了8小时），然后 Express `res.json()` 序列化后传给 Flutter，导致时间偏移。

**修复方案**：在 `BackEnd/server/models/db.js` 的连接池配置中添加 `dateStrings: ['DATE', 'DATETIME']`，让 mysql2 返回原始字符串而非 Date 对象，避免时区自动转换。

**同时修复**：
- `attendanceAnalyzer.js` 中 `yesterday.toISOString().slice(0, 10)` 的 UTC 偏移问题
- `checkinController.js` Excel 导出文件名的 `toISOString()` UTC 偏移问题

## 修复 OpenIM v3 API 兼容性问题（IM 仍然显示未登录）

**问题**：上一轮修了 SDK 未初始化的问题，但登录后 `imToken` 仍为 `null`，IM 依然显示"未登录"。

**根因**：后端 `openim.js` 使用的是旧版 OpenIM API 路径和参数格式，与 OpenIM v3 不兼容：
1. `/auth/user_token` 在 v3 中不存在，正确路径是 `/auth/get_user_token`
2. v3 的 `get_user_token` 不再接受 `secret` 参数，需要先获取管理员 token 再在 header 中传递
3. `/user/user_register` 请求体需要 `users` 数组格式
4. 所有请求需要 `operationID` header
5. `imConfig` 返回的地址是 `localhost`，手机无法访问

**修复**：
- `BackEnd/server/routes/openim.js` 完全重写 `OpenIMBridge` 类：
  - 新增 `getAdminToken()` 方法（带缓存），先获取管理员 token
  - `getUserToken()` 改为先获取 admin token，再在 header 中传递
  - `registerUser()` 改为 `users` 数组格式，用户已注册(errCode=1102)视为成功
  - 所有请求自动添加 `operationID` header 和 `token` header
  - 所有需要认证的方法都先获取 admin token
- `BackEnd/server/controllers/authController.js`：
  - `imConfig` 默认地址改为 `10.51.253.110` 而非 `localhost`
  - 增加详细的注册和获取 token 日志
- `MobileApp/lib/blocs/auth/auth_bloc.dart`：
  - `_onAppStarted` 恢复登录时从 secure storage 读取 `im_api_addr`/`im_ws_addr` 传给 IM 初始化
  - `_onLoggedIn` 保存 `imConfig` 到 secure storage（key: im_api_addr, im_ws_addr）
  - 登出时清理 im_api_addr 和 im_ws_addr
  - 大幅增加调试日志
