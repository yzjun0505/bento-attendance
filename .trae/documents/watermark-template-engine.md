# 水印模版引擎 (Watermark Template Engine) 重构计划

## 1. 总结 (Summary)
将原本侧重于“自由排版”与“简单开关”的水印样式画布，彻底重构为**“水印模版引擎”的创作者后台**。核心逻辑从“全局样式+元素堆叠”转变为**“版式结构库（骨架）” + “插槽数据与权限绑定（Slots & Binding）”**。管理员通过选择预设的 CSS 骨架，并为骨架的各个插槽绑定动态数据和前端修改权限，从而能排列组合出海量丰富的业务打卡水印模版。

## 2. 当前状态分析 (Current State Analysis)
- `Watermarks.vue` 目前左侧为模板基础设置与全局样式（颜色、字号等），通过 9宫格 控制水印模块的整体位置。
- 右侧面板提供固定元素的权限控制（强制显示、默认开启、隐藏），但所有元素依然只是上下堆叠，无法形成不同风格的版式（如印章、拍立得等）。
- 缺乏基于“插槽（Slot）”的内容注入机制，无法做到布局与内容解耦。

## 3. 拟定更改 (Proposed Changes)

### 3.1 左侧面板：版式结构库（骨架）
- **修改内容**：将左侧的“模板外观”和“全局样式”移除，替换为可视化的“版式骨架库”。
- **预设骨架列表**：
  1. `pure_text`：[ 左对齐纯文本 ] - 传统左上或左下角对齐的多行纯文本。
  2. `glass_card`：[ 底部毛玻璃卡片 ] - 底部吸附，具有毛玻璃背景，分为大标题、副标题和右侧信息。
  3. `stamp`：[ 悬浮印章风 ] - 右上角带有圆形印章边框的旋转文本，底部带说明。
  4. `polaroid`：[ 拍立得相框 ] - 整个画面被白色边框包裹，底部留白区域放置文本和 Logo。
- **数据结构**：`currentConfig.schema.layout` 保存选中的骨架 ID。

### 3.2 中间画布：真机效果实时预览
- **修改内容**：保留 iPhone 模型、背景图切换功能。
- **渲染逻辑**：取消 9宫格定位（骨架自带定位），根据选中的 `layout` 骨架以及绑定的 `slots` 数据，渲染出对应的 CSS 样式。对于未绑定数据的插槽，显示占位符（如 `[大标题]`）。

### 3.3 右侧面板：数据绑定与权限控制 (核心业务)
- **修改内容**：将右侧面板变为当前骨架的**“插槽配置区”**。
- **功能逻辑**：
  - 当左侧选中某个骨架后，右侧自动列出该骨架包含的插槽（如：大标题、副标题、Logo）。
  - 为每个插槽提供两个核心配置：
    1. **内容绑定**：下拉选择内置数据源（项目名称、打卡人姓名、实时时间、实时天气、GPS定位），或选择“自定义文本”、“自定义图片（Logo）”。如果选择自定义，则提供输入框。
    2. **手机端权限**：下拉选择 `locked` (🔒 锁定，员工不可改，强制抓取) 或 `unlocked` (🔓 开放，允许员工在 App 端微调/重新输入)。
- **数据结构**：`currentConfig.schema.slots` 对象，键为插槽 ID，值为 `{ binding: '...', customValue: '...', permission: 'locked' }`。

### 3.4 交互与代码结构
- **文件**：`BackEnd/web-admin/src/views/Watermarks.vue`
- 在 `<script setup>` 中定义 `layouts` 数组及其对应的 `slots`。
- 在 `toggleLayout` 时，初始化 `currentConfig.schema.slots`。
- 右侧面板通过 `v-for="slot in currentLayout.slots"` 动态渲染配置表单。

## 4. 假设与决定 (Assumptions & Decisions)
- **假设**：前端展示真实数据需要占位符，我们将使用模拟数据（如 `打卡人：张三`）在画布中预览绑定的数据源。
- **决定**：去掉之前的九宫格定位 (`schema.x`, `schema.y`)，因为复杂的骨架（如拍立得、毛玻璃卡片）自带了最完美的布局位置。
- **决定**：权限控制仅作为标识保存在 `schema` 中，供未来移动端读取使用。

## 5. 验证步骤 (Verification Steps)
1. 运行 `npm run dev` 打开系统。
2. 进入“水印样式画布”，点击“新建模板”。
3. 在左侧选择不同的版式骨架，观察中间画布布局是否切换。
4. 在右侧为各个插槽绑定不同的数据源（特别是测试“自定义文本”的输入联动），观察中间画布的内容是否实时更新。
5. 检查插槽的“锁定/开放”权限选项是否正确渲染和保存。
6. 点击“保存入库”，验证生成的 JSON schema 结构是否符合预期。
